# Восстановление полных DIV2K-фотографий

Это отдельный инференс готовых EMA-checkpoints. Переобучение и изменение исходного плана не требуются. Код и новые тесты подготовлены без запуска по просьбе пользователя; расход GPU-памяти и скорость полного кадра пока не измерены.

Каждая фотография подаётся генератору целиком, по одному forward на draw, без тайлов и изменения разрешения. Читаем исходные HR прямо из уже скачанного `DIV2K_valid_HR.zip`, проверяя SHA-256 из manifest. Используем те же image-level val/test splits, что при подготовке crop bank. Данные с интернета во время инференса не скачиваются.

LR синтезируется тем же `avg_pool2d(HR,4)`. Это проверка synthetic average-pooling ×4, не стандартный DIV2K bicubic benchmark и не восстановление произвольной фотографии с камеры. Если размеры HR не кратны 4, отражением дополняем низ/правый край на 0–3 пикселя. Перед сохранением и расчётом PSNR/SSIM убираем только добавленное: все оригинальные пиксели сохраняются. Native LR соответствует дополненному HR; raw/clipped LR-consistency считается на дополненном canvas и явно помечена в JSON.

## Запуск для текущей серии на кластере

```bash
cd /home/kkatsuba/mgm_i2i
git -c credential.helper= pull --ff-only
conda activate mgm_i2i
export PROJECT_DIR="$PWD"
export CONDA_ENV=mgm_i2i
export CONDA_SH="$(conda info --base)/etc/profile.d/conda.sh"
RUN_DIR="$PWD/cluster_runs/full_2h_20261013_202802"
mkdir -p slurm/logs

# Проверить соответствие индексов методам и seed, без загрузки моделей:
python scripts/cluster_infer_full.py --plan "$RUN_DIR/plan.json" --list

# Для текущего плана: индексы 0–5 = все шесть методов, seed 0.
# Шесть независимых задач, до шести GPU одновременно, восемь одинаковых фото.
sbatch --export=ALL --array=0-5%6 --job-name=mgm_full \
  slurm/full_images.sbatch "$RUN_DIR/plan.json" --limit 8

squeue -u "$USER"
```

Задачи нужно отправлять после завершения соответствующего обучения. По умолчанию 30 минут Slurm на задачу; это начальный лимит, а не измеренная оценка времени. Прогресс tqdm считает фотографии. Перед обработкой есть проверка архива, она может занять время без обновления полосы. Логи: `slurm/logs/full-JOBID_INDEX.out`.

Восемь фото берутся из фиксированного списка validation, один и тот же список у всех методов. Это диагностическая галерея, не отчёт по всем 50 validation-фотографиям. Для всех 18 checkpoints используй `--array=0-17%18`. Для всех фотографий своего split — `--limit 0` и увеличенный `--time` после измерения скорости на восьми фото. Можно явно выбрать фото через `--image-ids 0801 0802`, но IDs должны принадлежать указанному split: не используй произвольные IDs без проверки списка в manifest.

## Собрать сравнение после окончания задач

На login node, в том же conda-окружении, без GPU:

```bash
python scripts/cluster_infer_full.py --plan "$RUN_DIR/plan.json" --gallery-only
```

Главная страница: `$RUN_DIR/full_val/index.html`. При шести выполненных задачах она честно покажет `6/18`: остальные два seed не запускались в этом дополнительном сравнении. Если отдельная задача упала, её нет в completed runs и она перечислена в Missing runs.

Для каждой фотографии страница показывает HR, bicubic, projected bicubic и обе генерации всех завершённых методов. Превью ограничены 640 пикселями для быстрого просмотра. Нажатие открывает исходный полноразмерный PNG. На превью нельзя судить о мелких артефактах: сравнивай одинаковые области оригиналов при 100% масштабе.

Файлы одного метода, например:

```text
full_val/
  index.html                     # сравнение всех доступных методов
  mgm/seed0/
    index.html                   # отдельная галерея метода
    request.json                 # checkpoint/data hashes, precision, выбранные фото
    result.json                  # complete, метрики, время, peak GPU memory
    images.csv                   # PSNR/SSIM и diversity MSE по фотографиям
    0801/                        # пример ID; фактический список определяется split
      hr.png
      lr.png                     # реальный маленький вход, не увеличенный
      nearest.png                # LR увеличен для визуального сравнения
      bicubic.png
      projected_bicubic.png
      draw1.png
      draw2.png
      metrics.json
      *_preview.jpg
```

Чтобы открыть HTML на Mac, скачай **всю папку `full_val`**, сохранив вложенные папки и имена файлов. Страницы используют относительные ссылки, сервер и интернет не нужны. Например, из Terminal на Mac, заменив `CLUSTER_HOST` привычным адресом SSH-подключения:

```bash
scp -r kkatsuba@CLUSTER_HOST:/home/kkatsuba/mgm_i2i/cluster_runs/full_2h_20261013_202802/full_val ~/Downloads/
open ~/Downloads/full_val/index.html
```

## Память, повторный запуск и трактовка

По умолчанию FP32, как при crop-evaluation. Batch состоит из одного полного изображения, draws считаются последовательно; CPU считает PSNR/SSIM. Дополнительных зависимостей нет. Полный LPIPS не считается: новый режим предназначен прежде всего для визуального сравнения и не меняет `val_metrics.json`/`val_summary.md` основной серии. Метрики на PNG после округления могут немного отличаться от JSON: JSON считается до 8-битного сохранения.

Внутри генератора есть GroupNorm со статистиками по пространству. Из-за этого полный кадр и тот же кадр, обработанный тайлами, не эквивалентны даже с overlap. Автоматической подмены полного инференса тайлами нет. Кроме того, обучение было на 128×128, поэтому полное изображение — отдельная проверка переноса на другой размер входа. Результат может отличаться от crop-оценки.

Если полное фото не помещается в GPU, можно попробовать FP16 **для всех сравниваемых методов**, сохранив в новую папку:

```bash
sbatch --export=ALL --array=0-5%6 --job-name=mgm_full16 \
  slurm/full_images.sbatch "$RUN_DIR/plan.json" --limit 8 \
  --precision fp16 --output-root "$RUN_DIR/full_val_fp16"

# После окончания:
python scripts/cluster_infer_full.py --plan "$RUN_DIR/plan.json" \
  --output-root "$RUN_DIR/full_val_fp16" --gallery-only
```

Если FP16 даёт non-finite output, используй FP32 и GPU с большим объёмом памяти. Автоматическое понижение точности не выполняется. Заполненная папка метода не перезаписывается; для другой выборки, точности или повторной попытки после сбоя задай новую общую `--output-root`, затем передай её при сборке галереи. Исходные checkpoints, статусы обучения и crop-метрики не меняются.

Для held-out test есть `--split test`, но запускать его следует после фиксации протокола. Каждый полный HR имеет только один target: разнообразие двух draw само по себе не доказывает правильность условного распределения. Все фото и методы используют одинаковые детерминированные latents по ID и номеру draw; MSE использует нулевой latent. Показываем оба draw без выбора лучшего по HR.
